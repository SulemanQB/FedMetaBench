# FedMetaTemporal

FedMetaTemporal studies federated learning when client distributions change over time. It generates controlled sudden, gradual, recurring, or incremental drift and compares time-aware aggregation, meta-learning, and consolidation baselines.

## Algorithms

| Config name | Description |
| --- | --- |
| `temporal_fedavg` | Time-decayed aggregation of client updates |
| `temporal_maml` | Temporally weighted MAML with drift monitoring |
| `ewc_maml` | MAML with Elastic Weight Consolidation |

The algorithm factory follows `algorithm.name` in YAML, so changing the config changes the implementation used by the runner.

## Run

```bash
python -m pip install -r ../../requirements.txt
python run_experiment.py --config configs/smoke.yaml
python run_experiment.py --config configs/default.yaml
python tests/smoke_test.py
```

The smoke config uses six synthetic clients, sudden drift, a simple classifier, three rounds, and CPU. Results are written to `results/<experiment>_results.json` with `final.mean_accuracy` and a drift summary.

## Data, Models, and Configuration

Data is generated by `src/datasets/temporal_streams.py`. `model.type: simple` uses a feed-forward classifier; `model.type: neural_cde` selects the repository's GRU-based, time-aware sequence encoder. YAML controls drift type and count, client/sample budgets, task size, temporal decay, EWC strength, rounds, and seed.

## Technical Highlights and Limits

- Drift types are explicit experimental controls, making recovery behavior inspectable.
- Page-Hinkley and client drift monitors expose drift signals in the result artifact.
- Synthetic drift does not represent every real deployment pattern, and drift-triggered policy changes, richer prequential evaluation, and real streams remain areas for extension. The separate MetaDrift research track is outside this repository.
